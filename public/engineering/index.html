01 — Context

Built for shops that cannot go down

Retail shops in Venezuela run on modest Windows PCs with unreliable connectivity. Prices are anchored in USD while customers pay in bolivars (Venezuela's currency) at the official BCV rate (Banco Central de Venezuela, the country's central bank), which changes daily. A server, an internet connection or a subscription is not an option: the shop must keep selling when the network is down, and the data must stay on the shop's machine.

  • Offline-first: no cloud, no server, no web panel, no telemetry.
  • Exact money: multi-currency (USD/VES) with zero floating point.
  • Own the data: local database, verifiable backups, restore is sacred.
  • Small and light: a 2.97 MB installer that runs on entry-level hardware.

03 — The engineering, in code

Seven decisions, with the code that proves them

Short excerpts from the codebase — trimmed for space, not simplified. Each block is the function that does the work the text describes.

Money that cannot drift models.rs · lib.rs

Every amount in the core is a Decimal, and it travels as text, not as a binary float — sale signatures hash Decimal::to_string(), so a SHA-256 stays reproducible across platforms and versions. A malformed amount never becomes a silent zero: the backend has exactly one parser, and it fails loudly. 

pub fn total_bs(&self) -> Decimal {
    self.cantidades
        .iter()
        .zip(self.precios_usd.iter())
        .zip(self.tasas_bloqueadas.iter())
        .fold(Decimal::ZERO, |acc, ((q, p), t)| acc + *q * *p * *t)
}

fn decimal_de(texto: &str) -> Result<Decimal, UIError> {
    Decimal::from_str(texto.trim().replace(',', ".").as_str())
        .map_err(|_| UIError::new("monto invalido", "Se esperaba un numero decimal"))
}

Settlement sums per line with each line's locked rate, so one ticket can mix rates and still reconcile to the cent. The TypeScript side mirrors it with integer cents (Money.toCents, sum, usdToBsCents), and property tests assert exact sums and ≤1-cent reversibility.

fn clave_cronologica(fecha_unix: i64, id: &[u8]) -> Vec<u8> {
    let mut clave = Vec::with_capacity(8 + id.len());
    clave.extend_from_slice(&(fecha_unix as u64).to_be_bytes());
    clave.extend_from_slice(id);
    clave
}

Movements are keyed chronologically, so iter().rev() is recency order without sorting. IDs and names are fixed-size, zero-heap types (struct Sku([u8; 32], u8)), so scans don't allocate.

A schema you cannot break, backups that outlive versions db.rs

Records use positional bincode: adding, removing or reordering a field would corrupt every installed client. Persisted structs are therefore frozen, new features go to new trees, and backups are versioned and checksummed end to end.

A desktop app that heals itself datiolabs-ui/src/lib.rs · tasa_bcv.rs

The UI sends a heartbeat every 5 seconds; the shell stores it in an AtomicI64, and a watchdog thread reloads the window if it goes quiet for 30 seconds — with a 120-second cooldown so it cannot loop. 

std::thread::spawn(move || loop {
    std::thread::sleep(Duration::from_secs(10));
    let visto = ultimo.load(Ordering::Relaxed);
    if visto > 0 && ahora - visto > 30 && ahora - ultimo_reload > 120 {
        if let Some(ventana) = handle.get_webview_window("main") {
            let _ = ventana.reload();
        }
        ultimo.store(ahora, Ordering::Relaxed);
        ultimo_reload = ahora;
    }
});

The E2E suite validates it by freezing the renderer for 45 seconds and asserting the window comes back. The same discipline applies to state: the manual exchange rate is re-checked inside the same write lock that refreshes from BCV, so a stale scrape can never overwrite an operator's decision.

The only external input tasa_bcv.rs · db.rs

The BCV (Banco Central de Venezuela) publishes the rate as an HTML page, not an API. The shell fetches it hourly with a 30-second timeout, selects the USD box, normalizes the number (1.234,56 and 36,92 both parse), rejects zero and out-of-range values, and writes a signed rate event plus a cache. If the page changes or the network fails, the last rate stays. A manual rate set by the operator wins until they explicitly return to BCV, and the decision is re-checked under the same write lock as the write, so a scrape in flight cannot overwrite it. A missing rate blocks the sale instead of becoming zero. 

async fn scrapear_bcv(cliente: &reqwest::Client) -> Result<Decimal, UIError> {
    let html = cliente.get(URL_BCV).send().await?.error_for_status()?.text().await?;
    extraer_valor_usd(&html).ok_or(UIError { /* keep the last rate */ })
}

// "1.234,56" and "36,92" both parse; zero and out-of-range are rejected

It is a small pipeline, not a data platform: one source, one value, hourly. The engineering is in the failure contract: untrusted HTML, validation, fallback, operator override and a signed history. Six tests cover USD vs EUR, number formats, manual stickiness and the cache.

04 — Verification

Proof before promises

Three layers, from unit tests to a remote harness that clicks the real desktop application.

L1

Unit & contract

67 Rust tests in the core plus 6 in the desktop shell, and 92 frontend tests across 9 suites. The frontend/backend money contract is enforced by 1:1 contract tests. Rust core coverage: 95.15% of lines (92.59% of functions, 91.13% of regions, measured with cargo-llvm-cov on 2026-09-30).

L2

Property-based

proptest in Rust (property-based integration suites) and fast-check in TypeScript attack the money and inventory invariants with randomized cases.

L3

Real E2E over CDP

No mocks: a test build of the Tauri app exposes the Chrome DevTools Protocol and Playwright-core drives real clicks on the real WebView2. The harness runs from a Linux workstation over SSH/SCP against a Windows Server, with an isolated APPDATA and a scheduled interactive task. The test binary and the debug flag never reach the installer — verified in the final artifact.

Linux workstation scp/ssh → Windows Server CDP :9222 → Real Tauri app (WebView2)
  • The contract audit checks all 73 commands; the internal E2E harness exercises the user flows (cases in docs/e2e.md in the core repository).
  • Forged license rejected: the app refuses to operate (scenario A4).
  • Double-click on CHARGE creates exactly one sale: a replay returns the original ticket.
  • Five concurrent sales keep stock exact; oversell is rejected.
  • Midnight crossing (VET) and all 8 shift guards verified.
  • Unicode/XSS payloads in labels and notes are inert.
  • Upgrade over an installed version preserves data with 0 hash differences.
  • Final installer contains no debug flag and no debug port.
